# Architecture Decision Records (ADR)

Use ADRs to capture irreversible or high-impact technical decisions.

## When to write an ADR

- Data model or schema strategy changes
- Decision-contract or policy semantics changes
- New system boundary (service, module, persistence model)
- Trade-off decisions with meaningful alternatives

## Naming

- `ADR-0001-example-decision.md`
- Increment number sequentially.

## Required Sections

- Context
- Decision
- Alternatives considered
- Consequences
- Rollout/verification

## Status values

- Proposed
- Accepted
- Superseded
- Deprecated
